# 共用底座

这些条目是写作规格。用户要代写或挑错时按对应条目执行，不要把提示词原样回给用户。用户明确要提示词时，返回该条，已知信息填进方括号，没给的保留占位。

字数和章节名让位于用户的学校模板、期刊指南或当年项目指南。P0 里“先问再动笔”只在缺口会改变结构时执行。某一节材料已经够用就直接写，缺口标【待补】。

## 0. 用之前先看这三句

1. **提示词解决的是"表达"，不是"思考"。** 它能把你想清楚的写成学术语言，不能替你想出创新点。给的信息越具体（数据、现象、矛盾、你已有的结果），输出越像样。
2. **模型给的文献大概率是编的。** 作者、年份、期刊、卷期页、DOI、政策文号、统计数字，一律自己核。凡是它"顺手"补的引用，默认不可信。
3. **一次只让它做一件事。** "帮我写篇论文"必然得到正确的废话；"把这段的第三句改成论点句，其余不动"才能用。

## 1. 提示词的通用骨架

一条能用的学术提示词，通常包含六块：

| 要素 | 写法 | 反例 |
|---|---|---|
| 角色 | "你是[学科]方向的资深审稿人/基金评审" | 无 |
| 任务 | 一个动词，一个交付物 | "帮我看看" |
| 材料 | 粘贴原文、数据、要求、模板 | "我研究人工智能" |
| 约束 | 字数、结构、禁用词、不得编造 | 无 |
| 输出格式 | Markdown 表 / 分段 / 逐条 | 无 |
| 自检 | "先复述任务，再问我 3 个问题" | 无 |

**反例 → 正例**

- ❌「帮我写开题报告的国内外研究现状」
- ✅「以下是我读过的 12 篇文献的要点（粘贴）。请按学术争论把它们分成 3 个阵营，输出一张对照表，再用 800 字写评述，最后一句落到我的研究问题上。不要添加我没给你的文献。」

**不确定时不要编结论**

如果遇到不确定的学术结论不要自己编造，标注需要后续人工核验文献；不得生成不符合该学科领域常识的错误表述，比如不得出现已被学术共同体证伪的过时理论观点
全文所有表述均采用二次转述的原创化表达，对公开学术观点采用个性化逻辑重组方式改写，不得直接照搬现有文献的原句表述，在每段核心观点句的表述结构上调整语序逻辑，替换通用学术套话的常规表述范式，所有专业定义在符合学术准确性的前提下用自己的逻辑重新阐释，避免AI生成内容的同质化特征。同时在每一个引用观点的句末用[1][2]的上角标格式标注引用位置，后续人工核验时可直接对应到参考文献列表，进一步降低重复率误判概率。

执行时遵守 SKILL.md 的硬性规则：[n] 只对应用户已给的文献清单；没有清单就不要编编号。转述是为了不照搬、方便核验，不是对着查重率或 AIGC 分数反复改。

## 2. 万能底座（建议存成常用语，每个新对话先发）

### P0 · 学术合作者底座

```text
你是我长期的学术写作合作者，不是代笔。你的职责是：把我模糊的想法逼成清晰的问题，把我的草稿改成符合【学科】规范的表达，并在逻辑、事实、引用上挑错。

硬性规则：
1. 我给你的材料之外，不补充任何具体文献、数据、政策、案例；确需举例时标注【示例，待核实】。
2. 不确定就直说"不确定"，并告诉我应该去哪里、用什么检索式核实。
3. 每次只执行我要求的那一项任务，不顺手重写全文，不擅自增加观点。
4. 我的观点优先。你要改的是结构、逻辑、语气，不是立场。
5. 中文输出；专业术语首次出现时保留英文原词，格式：中文（English）。

现在先复述你对任务的理解（不超过 3 句），然后问我 3 个最关键的问题，等我回答后再动笔。
```

### P0.1 · 只提问模式（写之前用）

```text
先不要写任何正文。围绕【我的题目/方向】，列出为了写好它你必须知道、但我还没告诉你的 12 个问题，按重要性排序，每个问题说明"为什么它会影响写法"。
我回答后你再开始。
```

> 这一步能把 80% 的"AI 味"提前杀掉：它写得空，往往是因为你没给够。

### P0.2 · 审稿人模式

```text
切换到审稿人模式。你是【期刊档次，如 JCR 一区】的审稿人，方向是【】。
对下面这段文字，只做三件事：
1. 用一句话概括它实际说了什么（不是它想说什么）；
2. 指出 3 处逻辑跳跃或证据不足，引用原句；
3. 给出修改优先级：必须改 / 建议改 / 可不改。
不要替我重写。
```

### P0.3 · 引用核验模式

```text
下面是我文中的引用清单（作者 年份 期刊 标题）。逐条判断它是否可能真实存在，并说明判断依据。标注：高置信 / 存疑 / 高度疑似虚构。
对"存疑"和"疑似虚构"的，给出我应该在 PubMed / Web of Science / CNKI / Google Scholar 使用的检索式。
严禁替我补全作者、卷期、页码、DOI。
```

## 6. 质量与合规

### P45 · 事实与数据核查

```text
下面这段里有 N 个事实性断言（数字、政策、时间、比例）。请逐条拆出来，做成表：
断言原文 | 类型（统计数据/政策文件/文献结论/常识）| 我的置信度 | 建议核实来源（具体到机构与栏目）
不要替我判断真假，只帮我定位到哪里去核。
```

### P46 · 学术诚信边界（先问清楚再动笔）

```text
我要写【论文/开题报告/基金申请书】。请先告诉我：
1. 这类材料通常允许 AI 辅助到什么程度（检索、提纲、润色、翻译、成段生成分别怎么看）；
2. 哪些做法属于高风险（代写、伪造数据、伪造引用、规避检测）；
3. 如果我使用了 AI 辅助，通常应在哪里、如何声明；
4. 你建议我保留什么样的过程记录以备核查。
只讲通用惯例，并提醒我以本校/本刊/本项目指南为准。
```

> 现实提醒：基金申请书一般要求"由申请人本人撰写"，AI 只能用于检索、整理、润色；论文投稿多数期刊要求披露 AI 使用。别把"能生成"当成"可以交"。

## 7. 把提示词串成流水线

单条提示词只能救一段话，稳定的产出靠流程：

```text
① 素材 → ② 提问 → ③ 骨架 → ④ 逐节写 → ⑤ 审稿人挑错 → ⑥ 重写 → ⑦ 一致性与引用核查
```

| 阶段 | 用什么 | 产出 |
|---|---|---|
| ① 素材 | 自己整理：文献矩阵、数据表、预实验、政策原文 | 一个"事实底稿"文档 |
| ② 提问 | P0.1 | 12 个待答问题，补全信息 |
| ③ 骨架 | P1 / P5 / P15 / P35 | 目录或故事线，先审后写 |
| ④ 逐节写 | P6-P11 / P17-P23 / P33-P41 | 分节草稿，一节一个对话 |
| ⑤ 挑错 | P0.2 / P13 / P42 / P43 | 问题清单 |
| ⑥ 重写 | P24 / P29 | 改后稿 + 改动说明 |
| ⑦ 核查 | P0.3 / P30 / P45 | 引用核验表、一致性清单 |

**三个经验**

- 开新对话写新章节，别在一个对话里堆三万字，模型会忘掉前面的约束。
- 每次让它输出"改动说明"，你才知道它动了什么，也方便回退。
- 保留每一版的"事实底稿"，所有数字只从底稿来，不从模型嘴里来。
